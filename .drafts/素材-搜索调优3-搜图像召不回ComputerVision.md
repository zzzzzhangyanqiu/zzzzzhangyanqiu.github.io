# 搜索调优系列 3：搜「图像」召不回 Computer Vision（召回与查询理解）

## 核心张力（钩子）

**搜「视觉」能召回一堆纯英文的 Computer Vision 项目，搜「图像」却只能召回中文的——同一个意思，换个词召回集天差地别。搜「昇腾」更离谱，top3 全是大赛报名占位仓，官方核心仓一个都没有。**

灵魂：召回是一道**松紧的拿捏**——该进的要放进来（跨语言同义词）、不该进的要挡在外面（msm 收紧）、还不能把真正的区分词当噪声误删了（单字丢弃）。

写法建议：用"召回的**收 / 放 / 收过头**"三段式做主线，最后落到一个反直觉的方法论——**召回侧的改动，第 1 篇那把 NDCG 尺子量不出来**，得换口径。

---

## 大纲

**0. 开篇 · 一个能当场复现的判据**
- 搜「视觉」→ 召回纯英文 Computer Vision 项目；搜「图像」→ 只剩中文项目。
- 差别从哪来：`视觉 ↔ Computer Vision` 这条同义词早就配了，`图像` 那条没配。一个能亲手复现的对照，直接坐实"问题出在词库缺词，不是打分"。
- 引出本篇主题：召回这一层，光靠打分救不回来——东西没被捞进候选集，排序再准也没用。

**1. 召回的「收」· 多词过松，先收紧**
- 病：9 个召回子句 OR match，多词查询任一词命中即召回，噪声灌顶。
- 药：`minimum_should_match = 2<75%`（2 词全要、3 词要 2；**单词查询不受影响**），配空即热回滚。
- 数字：「深度学习推理框架」召回 13488 → 1181（-91% 噪声）。

**2. 召回的「放」· 跨语言，把该进的捞回来**
- 来源：站内搜索体验报告点出查询理解缺失——`cv ≠ 视觉`、中英不通（`记忆搜索` 零结果）、多词分散命中。先做成本最低、收益最明确的一环：同义词改写。
- 机制一句话讲清：ES 装了 `dynamic_synonym`，同义词只挂在 **search_analyzer**——**查询时扩展、不重建索引**，热更轮询生效。
- 昇腾的故事（本篇高潮）：中文「昇腾」和官方仓的英文命名「Ascend」原本不通；同义词把 `ascend` 这个 term 打进查询 → 直接命中 Ascend 命名空间仓。
  - top1~3：大赛报名占位仓 → **Ascend/pytorch、torchair、MindSpeed-LLM**（官方核心）。
  - top10 高质量官方仓：**0 → 8**。

**3. 收过头的反面 · 把区分词当噪声误删了**
- 病：`description.chinese` 的查询分析器丢弃单字 token——`分布式锁` → `分布式`（"锁"没了）；`锁`/`树`/`链` 单独查直接成空。
- 后果：查询里唯一的区分词"锁"根本没参与描述检索，只剩泛词"分布式"，叠加顶层 `minimum_should_match=1`（单词查询的必需品），单条泛词子句就放行 → 召回"分布式训练/微服务/编程"噪声灌顶。
- 数字：`description.chinese` 命中 `_count` 5361 → 保留"锁"后 **100**，砍 98% 噪声；top10 浮出真实的分布式锁库（redis-lock / spring-boot-klock-starter / lock-layer）。
- 注意分寸：直接放开单字过滤会引回单字噪声，修法要谨慎（末位单字保留 / phrase rescore），得先造"泛词+单字"测试词做消融——按下葫芦别起瓢。
- 这一段的味道：召回的"收"和"放"不是非黑即白，同一个 token 在不同位置可能是噪声、也可能是命门。

**4. 方法论高潮 · 第 1 篇那把尺子，这里量不出来**
- 反直觉现象：标准 A/B 跑「昇腾」，A=0.971、B=0.975，几乎持平——看着像没效果。
- 真相：同义词是 search-time 的，冻结基线 A 重放也走当前 analyzer、**同样吃到了召回**；NDCG 归一化后只衡量"召回集内部排序"、不衡量"召回集本身好不好"。A、B 都召回了官方仓，差值自然体现不出召回增益。
- 结论：**search-time 召回的成果，要用"召回内容质变 / top10 高质量仓数量"口径表达，不能用标准 A/B 的 NDCG 差值**（会误判成无提升）。这是第 1 篇"尺子"的延伸——尺子也有量程外的地方，得知道什么时候换尺子。
- 配套方法论：召回侧改动会同时改变基线 A（主表把回归藏住），归因要靠**消融重放**——同义词就用"查询级 analyzer 覆盖"隔离增量（覆盖成无同义的 `ik_smart` = A vs 有同义 = B），不必回滚词库。

**5. 收口 · 召回和排序是两套尺子**
- 召回决定"候选集里有没有这东西"，排序（第 2 篇）决定"它排第几"。两件事、两套度量。
- 把东西捞进来这件事，NDCG 量不出，但用户一眼能看出来（昇腾 0→8）。
- 系列收束：三篇合起来——评测（怎么知道好坏）、打分（怎么排序）、召回（捞什么进来），是同一套"凭数据"方法的三个面。

## 接地气素材包（约束 / 数字 / 怕）

### A. 约束（机制限制 / 来源）
- 需求来源：站内搜索体验报告（中软/泊松实验室 PPT）——cv≠视觉、中英不通、多词分散。
- 同义词只挂 search_analyzer，查询时扩展、不重建索引、热更轮询生效；原有 76 条早已生效，本轮补 26 条 + 主词典 extra_dict 补 7 主词。
- 主词库（extra_dict）改动影响**索引侧**分词，存量文档仍是旧分词，须随索引 v1_7 重建才对存量生效——重建前靠 synonyms 的 `昇腾↔Ascend` 兜底。

### B. 数字
- msm 收紧：深度学习推理框架 13488 → 1181（-91%）。
- 同义词消融：问题词 5 个 0.42 → 0.87（+0.45，4 升 1 平 0 降）；触发域真实热搜词 3 个 0.71 → 0.86（+0.15）；主流量 top30 ±0（0 词触发新增词条，零影响零风险）。
- 昇腾：top10 高质量官方仓 0 → 8。
- 单字丢弃：description.chinese `_count` 5361 → 100（-98%）。
- 评测口径陷阱：标准 A/B 昇腾 A=0.971 / B=0.975（持平，但不是没效果）。

### C. 怕（防翻车 / 分寸）
- msm 配空即热回滚；单词查询不受 msm 收紧影响（否则单字词搜不到）。
- 主流量回归只需查"查询分词是否触发新增词条"，不触发即零影响（top30 实测 0 触发）。
- 单字过滤别直接放开，先造测试词消融，避免引回单字噪声。
- `agent` 双向同义致 -0.05（查英文 agent 反向扩成"智能体"）——量级≈副本噪声，可改单向 `智能体 => agent` 消除，暂未做。
