## 信号量
信号量机制是一种功能较强的机制，可以用来解决互斥与同步问题，它只能被两个标准的原语wait(S) 和 signal(S)来访问，也可以记为“P操作”和“V操作”。
    
```c
wait(S){
   while(S<=0);
   S = S - 1;    
}

signal(S){
   S = S + 1;
}
```

wait(P操作):请求当前资源S，如S<=0时，证明已经没有资源可以分配，线程会处于"忙等"状态，除非有其它线程调用signal(S)释放资源后才会继续执行。

signal(V操作):释放当前资源，表示任务已经执行完成。

信号量机制被用来解决"如何使用有限的资源执行任务"，举几个实际生活的例子。

### 吃饭问题：
有九个人需要吃饭，但是桌子上只有三套餐具，只能同时允许三个人同时用餐，使用信号量思想如下：
    
```java
int semaphore = 3;  //指定信号量，此时信号量为餐具数量

wait(semaphore); //请求资源

eat();      //开始吃饭

signal(semaphore);      //吃完饭后释放资源
```

### 读书问题：
有十个人都想读书，但是书只有四本，只能允许四个人一起读：

```java
int semaphore = 4;  //指定信号量，此时为书籍数量

wait(semaphore); //请求资源

readBook();      //开始读书

signal(semaphore);      //读书后释放资源
```

相信到了这里你已经看懂了，信号量其实就是我们之前所说的"有限的资源"，下面我们一起来看看在Java多线程中的应用：

### Semaphore：

```java
public class Test {
    public static void main(String[] args) {
        //JAVA中提供的信号量工具
        Semaphore semaphore = new Semaphore(3); //只有三个餐位

        for (int i = 0; i < 9; i++) {      //模拟九个人吃饭
            new Thread(new EatThread(i, semaphore)).start();
        }
    }
```


​    
```java
    private static class EatThread implements Runnable {

        private int seq;

        private Semaphore semaphore;

        public EatThread(int seq, Semaphore semaphore) {
            this.seq = seq;
            this.semaphore = semaphore;
        }

        /**
         * When an object implementing interface <code>Runnable</code> is used
         * to create a thread, starting the thread causes the object's
         * <code>run</code> method to be called in that separately executing
         * thread.
         * <p>
         * The general contract of the method <code>run</code> is that it may
         * take any action whatsoever.
         *
         * @see Thread#run()
         */
        @Override
        public void run() {
            try {
                //获取资源 等同于wait(S){
                semaphore.acquire();

                System.out.println("No:" + seq + "开始吃饭！");

                if (seq % 3 == 0) {      //假设0 3 6 三个人吃的特别慢
                    System.out.println("No:" + seq + "吃的有点慢。。竟然还在吃！");
                    Thread.sleep(5000);
                }

            } catch (Exception e) {
                e.printStackTrace();
            } finally {
                System.out.println("No:" + seq + "吃完了！");
                //吃完饭要释放资源 等用于signal(S){
                semaphore.release();
            }
        }
    }
}  
```

### CyclicBarrier：
实际生活中，总有一些特殊的场景，拿上面的例子来说，如果有的餐馆三个人都吃完之后，才能进入下一批人，之前的代码就不适用了，针对这种情景，Java中为我们提供了CyclicBarrier工具类，有两个主要的API：

```java
cyclicBarrier.await();  //申请资源

cyclicBarrier.reset();  //重置资源，等待其它线程
```

此工具类中，如果1，2都用餐完成，需要等待3也用餐完成之后，才会释放资源，需要注意的是，如果有十个人，那9用餐完成之后会一直等待，等待其它两个线程完成，但是此时已经没有多余的线程了，代码则会抛出异常，可以通过cyclicBarrier.reset设置超时时间，来决定等待的时间。
