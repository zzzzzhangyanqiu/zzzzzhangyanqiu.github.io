## 定义：
> 为其他对象提供一种代理以控制对这个对象的访问。在某些情况下，一个对象不适合或者不能直接引用另一个对象，而代理对象可以在客户端和目标对象之间起到中介的作用。

## 组成：
学习代理模式之前，我们先来了解一下代理模式中的各个组成部分。
### 抽象角色：
通过接口或抽象类声明真实角色实现的业务方法。

### 代理角色：
实现抽象角色，是真实角色的代理，通过真实角色的业务逻辑方法来实现抽象方法，并可以附加自己的操作。

### 真实角色：
实现抽象角色，定义真实角色所要实现的业务逻辑，供代理角色调用。

## 实现：

下面我们用java来实现代理模式，实现代理模式主要有三种手段，分别是：静态代理，动态代理和cglib方式。

### 静态代理：

> 上面说到，代理模式主要由三种对象组成，这里我们模拟房东-中介-租客的场景，正常来说租客直接向房东交房租，但是因为一些原因，中间要设计到中介，这里的中介就是我们所说的代理角色，他代替租客来完成交房租的这个事情。

1. 首先创建租客接口，也是代理模式中的抽象对象：


  ​    

```java

/**
  *@author zhangyq
  *租客接口，定义了支付房租方法
   */
public interface Tenant {

    /***

        支付房租
        **/
    void pay();

}

```


2. 创建租客接口的实现类，对应代理模式中的真实角色，决定了真实的交房租行为：

    ```java
    /**
    	 * @author zhangyq
    	 */
    public class TenantImpl implements Tenant {
        /***
    	     * 支付房租
    	     * **/
        @Override
        public void pay() {
            System.out.println("支付了本月的房租");
        }
    }
    ```

    

3. 最后创建我们的中介类，对应代理角色，中介类的功能很明显，就是代替租客交房租，顺便收取一些中介费：

    ```java
    /**
         * @author zhangyq
         */
    public class TenantProxy implements Tenant {
        private Tenant tenant;
    
        public TenantProxy(Tenant tenant) {
            this.tenant = tenant;
        }
    
        /***
         * 支付房租
         * **/
        @Override
        public void pay() {
            System.out.println("嘿嘿，我要先收取一点中介费！");
            tenant.pay();
        }
    } 
    ```

4. 使用时，只需要让中介去交房租就好：

    ```java
    /**
         * @author zhangyq
         */
    public class Test {
        public static void main(String[] args) {
            //创建租客类
            Tenant tenant = new TenantImpl();
            //创建中介类 传入租客类
            Tenant tenantProxy = new TenantProxy(tenant);
            //直接调用中介交房租就可以了
            tenantProxy.pay();
        }
    }
    ```

    

运行结果为：

​		
​		`嘿嘿，我要先收取一点中介费！
​		支付了本月的房租`

可以看出静态代理模式比较简单，但是局限性较大，如果租客类想新增个方法，代理类中同样需要新增一个方法，拓展起来比较麻烦，所以Java为我们提供了动态代理的方式。

### 动态代理
> 相比静态代理，动态代理类不需要和实现类实现同一个接口，只需要实现Java中为我们提供好的InvocationHandler即可

抽象对象和实现类与静态代理中一样，这里不在表述。

#### 代理类（相当于中介角色）： ####
```java
public class TenanDynamicProxy implements InvocationHandler {

    private Tenant tenant;

    public TenanDynamicProxy(Tenant tenant) {
        this.tenant = tenant;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("我要用动态代理收点中介费");
        method.invoke(tenant, args);
        return null;
    }
}
```


#### 客户端使用 ####
```java
	//创建租客类
    Tenant tenant = new TenantImpl();

    //动态代理类
    TenanDynamicProxy tenanDynamicProxy = new TenanDynamicProxy(tenant);

    //使用动态代理创建出代理对象
    Tenant user = (Tenant) Proxy.newProxyInstance(tenant.getClass().getClassLoader(), tenant.getClass().getInterfaces(), tenanDynamicProxy);

    user.pay();
```

运行结果为：

```java
我要用动态代理收点中介费
支付了本月的房租
```



#### 分析 ####
动态代理中，比较重要的代码就是`Proxy.newProxyInstance` 这个方法中一共有三个参数：实现类的加载器，实现类的接口（原因是要给每一个实现类的方法加入代理类中的代码），动态代理类。Java会根据这三个参数使用反射的方式创建对象。

可以看出，动态代理相比静态代理，代理类不需要和实现类实现同一个接口，而是实现Java中提供好的动态代理接口，不需要处理每个实现类的方法，当然，如果想只对单独一个方法进行处理，也可以在代理类中使用`method.getName()`进行判断。

#### 问题 ####
JDK的动态代理用起来非常简单，但它有一个限制，就是使用动态代理的对象必须实现一个或多个接口。如果想代理没有实现接口的继承的类，该怎么办？现在我们可以使用CGLIB包
### CGLIB
> CGLIB是一个强大的高性能的代码生成包。它广泛的被许多AOP的框架使用，例如Spring AOP，为他们提供方法的interception（拦截）hibernate也使用CGLIB来代理单端single-ended(多对一和一对一)关联（对集合的延迟抓取，是采用其他机制实现的）。EasyMock和jMock是通过使用模仿（mock）对象来测试java代码的包。它们都通过使用CGLIB来为那些没有接口的类创建模仿（mock）对象。
CGLIB包的底层是通过使用一个小而快的字节码处理框架ASM，来转换字节码并生成新的类。除了CGLIB包，脚本语言例如Groovy和BeanShell，也是使用ASM来生成java的字节码。

#### 动态代理类 ####

```java
public class TenantHandler implements MethodInterceptor {
    @Override
    public Object intercept(Object o, Method method, Object[] objects, MethodProxy methodProxy) throws Throwable {
        System.out.println("我要通过cglib收取一点中介费");
        methodProxy.invokeSuper(o, objects);
        return null;
    }
}
```

#### 客户端使用 ####

```java
Enhancer enhancer = new Enhancer();

enhancer.setSuperclass(TenantImpl.class);

enhancer.setCallback(new TenantHandler());

Tenant user = (Tenant) enhancer.create();

user.pay();
```

运行结果为：

```java
我要通过cglib收取一点中介费
支付了本月的房租
```

可以看出，cglib方式比较简单，代理类不需要依赖任何实现类，达到了完全解耦，如果想更换代理类，也只需要更改`enhancer.setCallback(new TenantHandler());`即可，典型的应用就是Spring AOP，这个我们下次再分析。三种模式没有哪种对错，在实际使用中，根据业务来选择使用方式才是最合适的做法。
