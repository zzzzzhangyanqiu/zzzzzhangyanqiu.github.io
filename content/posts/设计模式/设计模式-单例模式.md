## 单例模式

> 单例模式是一种软件设计模式，它将类的实例化限制为一。 当需要一个对象来协调整个系统的操作时，这非常有用。该术语来自单身人士的数学概念。

单例模式比较简单，相信就算你没有学习过，也肯定用过。单例模式保证了在整个系统中，一个类只存在一个实例。首先介绍一下单例模式的两种实现。

### 饿汉式加载

饿汉式加载，顾名思义，就是无时无刻都拥有着一个类的示例，饿汉式实现比较简单，如下

```java
//在类初始化时就直接加载
private static SingletonObject singletonObject = new SingletonObject();

public static SingletonObject getInstance(){
    return singletonObject;
}
```

### 懒汉式加载

与饿汉式加载先对应的是懒汉式加载（也叫`Lazy initialization`、`Lazy loading`等）。懒汉式与饿汉式最大的区别就是只有在用到了单例类时，才会去初始化，如下

```java
//初始化时不再加载
private static SingletonObject singletonObject = null;

public static SingletonObject getInstance(){

    if(singletonObject == null) {			//1
        singletonObject = new SingletonObject();		//2
    }

    return singletonObject;
}
```

上述代码很好的描述了懒汉式的思想，不过在并发环境下有一个很大的问题，例如我们有两个线程`A/B`，在`A`线程进入到了1处的判断后，还没有来得及执行2处的代码，此时`B`线程也进入了1处的判断，这样两个线程都分别实例化了`singletonObject`，不是我们想要的结果。

为了解决上述问题，有人提出了：我们把`getInstance()`方法加个锁不就可以了么，如下

```java
//初始化时不再加载
private static SingletonObject singletonObject = null;

public static synchronized SingletonObject getInstance(){

    if(singletonObject == null) {
        singletonObject = new SingletonObject();
    }

    return singletonObject;
}
```

这样一来，在并发环境下看起来是没有什么问题了，但是大家好好想一下，每次调用`getInstance()`方法都要同步等待，如果并发量比较高的情况下，此操作会严重影响性能。看来这种办法也不是最合适的，那还有其它的办法么？这时候又有人提出了`双重检查锁定（double-checked locking）`写法。如下

```java
//初始化时不再加载
private static SingletonObject singletonObject = null;

public static SingletonObject getInstance() {
    //第一次检查
    if (singletonObject == null) {				//1
        synchronized (SingletonObject.class) {
            //第二次检查
            if (singletonObject == null) {		//2
                singletonObject = new SingletonObject();
            }
        }
    }
    return singletonObject;
}
```

OK，这种方式看起来没什么问题了，性能也不会受到影响，也可以实现多线程的单例。但是，这种写法是错误的。可以有的同学心里是：WTF？这样还是错误的？别着急，现在我们一起来分析一下此写法的弊端。由于`JVM`的机制，`singletonObject = new SingletonObject();`这行代码会分为两步执行。

1. 初始化`SingletonObject`，并分配内存空间。
2. 将1中分配的内存地址赋值给`singletonObject `字段。

而且由于`JVM`的指令重排优化机制，这两个操作也不会保证顺序执行，也可能会先执行2，再执行1。这样存在的问题就是，`A/B`两个线程同时进入1处判断之后，`A`线程首先进入了2处的判断，此时`singletonObject`字段可能已经被赋值了内存地址，但是对象还没有初始化。这样`B`不会进入2处的判断而直接返回此字段。注意，此时的`singletonObject`字段只是引用了一个未初始化的`SingletonObject`，这样程序就肯定会出错。



为了解决上述问题，有两种解决方案，第一种就是使用`volatile`关键字来禁止`JVM`的指令重排，完整代码如下

```java
//使用volatile禁止指令重排
private static volatile SingletonObject singletonObject = null;

public static SingletonObject getInstance() {
    //第一次检查
    if (singletonObject == null) {
        synchronized (SingletonObject.class) {
            //第二次检查
            if (singletonObject == null) {
                singletonObject = new SingletonObject();
            }
        }
    }
    return singletonObject;
}
```

第二种方式就是使用静态内部类的方式，`JVM`的保证了多线程环境下，一个类同时只能被一个线程加载，保证了线程安全问题，而且静态内部类是使用时才会加载，也保证了延迟加载的效果。

```java
//静态内部类
private static class StaticInnerClass {
    private static SingletonObject singletonObject = new SingletonObject();
}

public static SingletonObject getInstance() {
    return StaticInnerClass.singletonObject;
}
```

相比于第一种方式，第二种显然更加简洁明了，实际使用时可根据自身情况使用不同的方式。
