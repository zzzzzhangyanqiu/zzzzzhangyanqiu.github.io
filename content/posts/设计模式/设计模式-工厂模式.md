## 工厂模式

> 工厂模式是一种创建模式，它使用工厂方法来处理创建对象的问题，而无需指定将要创建的对象的确切类

举个栗子

![](/images/oss/%E5%8D%9A%E5%AE%A2/%E4%B8%BE%E4%B8%AA%E6%A0%97%E5%AD%90.jpg)

比如我们现在正在做一个图书馆的管理系统，图书馆中有很多本书，比如我们的名著《水浒传》、《西游记》。

最初可能是这样的结构（正常不会这样设计，这里只是为了举例说明）

```java
/**
 * 书籍对象
 * **/
public class Book {
    /**
     * 书籍名称
     **/
    private String name;

    /**
     * 初始化创建
     **/
    public Book(String name) {
        this.name = name;
        switch (name) {
            case "threeKingdoms":
                //初始化三国演义书籍
                break;
            case "waterMargin":
                //初始化水浒传书籍
                break;
            default:
                //错误处理
                break;
        }
    }

    /**
     * 阅读书籍
     **/
    public void read() {
        switch (name) {
            case "threeKingdoms":
                //阅读三国演义相关代码...
                break;
            case "waterMargin":
                //阅读水浒传相关代码...
                break;
            default:
                //错误处理
                break;
        }
    }

}

```

然后在使用时

```java
Book book = new Book("threeKingdoms");
book.read();
```

以上代码看似解决了需求，但是还是存在很多的问题。

1. 随着业务量的增长，`Book`类的代码将会越来越多，越来越难以维护。
2. `Book`类中存在着大量重复的`switch`分支判断。
3. `Book`类中做了两个工作，分别是书籍的创建和阅读，我们如果要增加书籍，需要同时修改这两处，这也违背了设计模式中的单一职责原则：**单一职责原则（SRP：Single responsibility principle），它规定一个类应该只有一个发生变化的原因。**
4. 如果以后要增加新的书籍，还要修改`Book`类，这也违反了设计模式中的开闭原则：**开闭原则(Open-Closed Principle, OCP)：一个软件实体应当对扩展开放，对修改关闭。即软件实体应尽量在不修改原有代码的情况下进行扩展。**

为了解决这些问题，我们用工厂模式来改造，首先来介绍简单工厂模式。

### 简单工厂模式

简单工厂模式中有三个角色组成，分别是

- 简单工厂角色：负责创建产品对象
- 抽象产品角色：产品的抽象类
- 具体产品角色：产品的具体对象

UML类图为

![](/images/oss/%E5%8D%9A%E5%AE%A2/%E7%AE%80%E5%8D%95%E5%B7%A5%E5%8E%82%E6%A8%A1%E5%BC%8FUML.png)

观察上面的代码，你会发现基本所有的书籍都有相同的功能，那就是被阅读，首先我们抽象出公共的书籍对象。

```java
/**
 * 书籍的抽象对象
 * **/
public interface Book {
    /**
     * 阅读书籍
     * **/
    void read();
}

```

再创建我们的具体产品类

```java
/**
 * 三国演义
 * **/
public class ThreeKingdoms implements Book {
    /**
     * 阅读书籍
     **/
    @Override
    public void read() {
        System.out.println("正在阅读三国演义");
    }
}

/**
 * 水浒传
 * **/
public class WaterMargin implements Book {

    /**
     * 阅读书籍
     **/
    @Override
    public void read() {
        System.out.println("正在阅读水浒传");
    }
}

```

最后创建我们的简单工厂

```java
static Book create(String name){
    switch (name) {
        case "threeKingdoms":
            //初始化三国演义书籍
            return ThreeKingdoms::new;
        case "waterMargin":
            //初始化水浒传书籍
            return WaterMargin::new;
        default:
            return null;
    }
}
```

使用时就直接可以调用工厂类的方法

```java
Book threeKingdoms = BookFactory.create("threeKingdoms");
threeKingdoms.read();
```

这样一来，工厂类只负责对象的创建，书籍类只负责阅读，遵循了**单一职责原则**。而且如果想要拓展，我们也只需创建一个书籍对象继承`Book`接口，修改工厂类即可，

### 抽象工厂模式

上述方式随着业务的增长，也会存在一个问题，就是工厂模式中的代码还是会越来越多，并且不同种类的书籍都混在一个工厂类中也很难维护。这时候我们就要把产品分类，引出产品族的概念

产品族：同一种类的产品为一个产品族，比如中国的书籍就是一个产品族，外国的书籍又是一个产品族。

了解了产品族的概念之后，我们就来改写简单工厂模式。讲工厂类抽象，而每一个产品族就是一个具体的工厂对象。

抽象工厂模式的UML类图

![](/images/oss/%E5%8D%9A%E5%AE%A2/%E6%8A%BD%E8%B1%A1%E5%B7%A5%E5%8E%82%E6%A8%A1%E5%BC%8FUML.png)

首先创建工厂模式的抽象类

```java
/**
     * 工厂类只负责创建
     * **/
abstract Book create(String name);
```

然后是工厂的实际对象，这里我们只模拟两个产品族：中国书籍和外国书籍，创建两个工厂对象分别对应两个产品族

```java
/**
 * 代表中国书籍产品族的工厂
 * **/
public class ChineseBookFactory extends AbstractFactory {

    @Override
    Book create(String name) {
        switch (name) {
            case "threeKingdoms":
                //初始化三国演义书籍
                return ThreeKingdoms::new;
            case "waterMargin":
                //初始化水浒传书籍
                return WaterMargin::new;
            default:
                return null;
        }
    }
}


/**
 * 代表外国书籍产品族的工厂
 * **/
public class ForeignBookFactory extends AbstractFactory {
    @Override
    Book create(String name) {
        switch (name) {
            case "thinkingInJava":
                return ThinkingInJava::new;
            case "effectiveJava":
                return EffectiveJava::new;
            default:
                return null;
        }
    }
}
```

使用

```java
//根据不同的产品族选择不用的工厂类
AbstractFactory chinese = new ChineseBookFactory();
Book book = chinese.create("threeKingdoms");
book.read();
```



**注意！！！**此处为了简洁的描述工厂模式的思想，忽略了部分代码（如讲产品族抽象）。在实际使用中，要根据不同情况灵活运用，我们要学习背后的思想而不是code。
