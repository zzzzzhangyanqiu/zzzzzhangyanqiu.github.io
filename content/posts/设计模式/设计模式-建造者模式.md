## 建造者模式

> 建造者模式是一种设计模式，旨在为面向对象编程中的各种对象创建问题提供灵活的解决方案。建造者模式的目的是将复杂对象的构造与其表示分开。

### 问题的由来

假设我们现在要设计一个车辆系统，大家都知道，一辆车包含了很多的配件，如轮胎、车身颜色、发动机、油泵、变速器等等。首先我们根据面向对象的原则来抽象出车辆对象。

```java
public class Vehicle {
    /**
     * 车轮数量
     * **/
    private int wheel;

    /**
     * 颜色
     * **/
    private String color;

    /** 发动机 **/
    private String engine;

    /** 油泵 **/
    private String pump;

    /** 变速器 **/
    private String gearbox;
    
    //省略getter()/setter()/toString()方法..
}
```

实际使用时，有不同种类的车辆，首先来制作一个小汽车（为了方便，这里直接使用`main()`方法）

```java
public static void main(String[] args) {
    System.out.println(getCar());
}

//初始化一个红色的小汽车
static Vehicle getCar() {
    Vehicle vehicle = new Vehicle();
    vehicle.setColor("红色");
    vehicle.setWheel(4);    //汽车有四个车轮
    vehicle.setEngine("小汽车的发动机");
    vehicle.setGearbox("小汽车的变速器");
    vehicle.setPump("小汽车的油泵");
    return vehicle;
}
```

OK，现在我们解决了小汽车。很快，新的需求又来了，这次需要增加一个摩托车，我们继续修改之前的源代码，增加一个`getMotorcycle()`方法

```java
//初始化一个黑色的摩托车
static Vehicle getMotorcycle() {
    Vehicle vehicle = new Vehicle();
    vehicle.setColor("黑色");
    vehicle.setWheel(2);    //摩托车有两个车轮
    vehicle.setEngine("摩托车的发动机");
    vehicle.setGearbox("摩托车的变速器");
    vehicle.setPump("摩托车的油泵");
    return vehicle;
}
```

问题来了，可以看到，我们构造的两个对象大体上都是相同的，两个方法的重复度非常高，而且每次增加一种车辆都要修改此类，违背了我们**开闭原则**。

为了解决上述问题，这个时候就要引出我们的建造者模式了。**建造者设计模式的目的是将复杂对象的构造与其表示分开**

建造者设计模式解决了以下问题

- 类（相同的构造过程）如何创建复杂对象的不同表示？
- 如何简化包含创建复杂对象的类？

仔细观察上面的两句话，是不是特别符合我们现在的情况呢。

### 建造者模式介绍

首先来看一下建造者模式的`UML`图

![](https://suiyueranzly.oss-cn-beijing.aliyuncs.com/%E5%8D%9A%E5%AE%A2/Builder_UML_class_diagram.svg)

建造者模式分为以下几个角色

- `Builder`（建造者接口）：用于创建对象（产品）的抽象接口，`Builder`中有两种方法，一种是`build*()`方法来构造产品的各个属性，一种是`getResult()`方法来获取最终的产品。
- `ConcreteBuilder`（实际建造者）：建造者接口的实现类，每种产品对应一个类，如小汽车建造类，摩托车建造类等。
- `product`（产品类）：对于一类产品的抽象。
- `director`（导演类）：用于控制对象（产品）的建造过程。

### 改造

了解了建造者模式后，我们就可以使用此模式来改造我们的车辆系统了，首先车辆的抽象对象不变，作为建造者模式的`product`角色

```java
public class Vehicle {
    /**
     * 车轮数量
     * **/
    private int wheel;

    /**
     * 颜色
     * **/
    private String color;

    /** 发动机 **/
    private String engine;

    /** 油泵 **/
    private String pump;

    /** 变速器 **/
    private String gearbox;

    //省略getter()/setter()/toString()方法..
}
```

然后抽象出我们`Builder`角色（建造者接口）

```java
public abstract class VehicleBuilder {

    protected Vehicle vehicle = new Vehicle();

    /**
     * 构建车轮数量
     **/
    protected abstract void buildWheel();

    /**
     * 构建车辆颜色
     **/
    protected abstract void buildColor();
    /**
     * 构建发动机
     **/
    protected abstract void buildEngine();
    /**
     * 构建油泵
     **/
    protected abstract void buildPump();
    /**
     * 构建变速器
     **/
    protected abstract void buildGearbox();


    /** 得到最终对象 **/
    public Vehicle getResult() {
        return vehicle;
    }
}
```

第三步，创建小汽车的建造类，也就是`ConcreteBuilder`角色

```java
/**
     * 构建车轮数量
     **/
@Override
protected void buildWheel() {
    vehicle.setWheel(4);
}

/**
     * 构建车辆颜色
     **/
@Override
protected void buildColor() {
    vehicle.setColor("red");
}

/**
     * 构建发动机
     **/
@Override
protected void buildEngine() {
    vehicle.setEngine("小汽车的发动机");
}

/**
     * 构建油泵
     **/
@Override
protected void buildPump() {
    vehicle.setGearbox("小汽车的变速器");
}

/**
     * 构建变速器
     **/
@Override
protected void buildGearbox() {
    vehicle.setPump("小汽车的油泵");
}
```

第四步，创建导演类

```java

private VehicleBuilder vehicleBuilder;

public VehicleDirector(VehicleBuilder vehicleBuilder) {
    this.vehicleBuilder = vehicleBuilder;
}

public Vehicle getResult() {
    vehicleBuilder.buildColor();
    vehicleBuilder.buildWheel();
    vehicleBuilder.buildEngine();
    vehicleBuilder.buildPump();
    vehicleBuilder.buildGearbox();
    return vehicleBuilder.getResult();
}
```

客户端使用时，就可以直接调用

```java
Vehicle vehicle = new VehicleDirector(new CarBuilder()).getResult();

System.out.println(vehicle);
```

这样一来，如果我们想拓展一个摩托车种类，也只需要创建一个`MotorcycleBuilder`类就可以了，完全不需要修改源代码。

### 优化

之前说过，学习设计模式时不要死板，重点是背后的核心思想，我们完全可以在遵循这个思想的基础上做出一些优化，

比如，使用配置文件来记录当前的建造器，导演类中就可以直接读取

```properties
#使用的默认建造器
bulider.default.class =com.design.bulider.CarBuilder
```



```java
private static VehicleBuilder vehicleBuilder;

private static Properties prop = new Properties();

private static final String CLASS_NAME_KEY = "bulider.default.class";

static  {

    //读取到在配置文件中配置的默认建造类
    InputStream resourceAsStream = Test.class.getClassLoader().getResourceAsStream("application.properties");

    try {
        prop.load(resourceAsStream);
        //获取执行器
        Class<?> classzz = Class.forName(prop.getProperty(CLASS_NAME_KEY));

        vehicleBuilder = (VehicleBuilder) classzz.newInstance();

    } catch (Exception e) {
        //日志记录
        e.printStackTrace();
    }

}

public static Vehicle getResult() {
    vehicleBuilder.buildColor();
    vehicleBuilder.buildWheel();
    vehicleBuilder.buildEngine();
    vehicleBuilder.buildPump();
    vehicleBuilder.buildGearbox();
    return vehicleBuilder.getResult();
}
```

客户端直接获取对象

```java
Vehicle vehicle = VehicleDirector.getResult();

System.out.println(vehicle);
```



还有另外的手段来优化，比如省略导演类，直接把`getResult()`放在抽象建造类中实现，并且使用链式调用的方式，再加上之前提到的使用配置文件，最终代码如下

`VehicleBuilder.java`

```java
public abstract class VehicleBuilder {

    protected static Vehicle vehicle = new Vehicle();

    private static VehicleBuilder vehicleBuilder;

    private static Properties prop = new Properties();

    private static final String CLASS_NAME_KEY = "bulider.default.class";

    static {

        //读取到在配置文件中配置的默认执行类
        InputStream resourceAsStream = Test.class.getClassLoader().getResourceAsStream("application.properties");

        try {
            prop.load(resourceAsStream);
            //获取执行器
            Class<?> classzz = Class.forName(prop.getProperty(CLASS_NAME_KEY));

            vehicleBuilder = (VehicleBuilder) classzz.newInstance();

        } catch (Exception e) {
            //日志记录
            e.printStackTrace();
        }

    }

    /**
     * 构建车轮数量
     **/
    protected abstract VehicleBuilder buildWheel();

    /**
     * 构建车辆颜色
     **/
    protected abstract VehicleBuilder buildColor();

    /**
     * 构建发动机
     **/
    protected abstract VehicleBuilder buildEngine();

    /**
     * 构建油泵
     **/
    protected abstract VehicleBuilder buildPump();

    /**
     * 构建变速器
     **/
    protected abstract VehicleBuilder buildGearbox();


    /**
     * 得到最终对象
     **/
    public static Vehicle getResult() {
                //链式调用
        vehicleBuilder.buildWheel().buildColor()
                .buildEngine().buildGearbox().buildPump();
        return vehicle;
    }
}
```


### 优缺点

建造者模式的优点包括：

- 完美遵循**开闭原则**，拓展方便。
- 省略了复杂对象的构建过程，客户端可以直接使用。
- 将对象的构建和表示分开，也遵循了**单一职责原则**.

当前，建造者模式也有缺点：

- 需要为每种不同类型的产品创建单独的`ConcreteBuilder`，如果产品类型较多，产生的类较多。
- 使用建造者模式的前提必须是多种类型的产品有相同或者类似的建造过程，
