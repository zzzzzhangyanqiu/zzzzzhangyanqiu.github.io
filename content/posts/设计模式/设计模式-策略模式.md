## 策略模式

今天我们一起来学习一个设计模式——策略模式，那什么是策略模式呢，简单的来说，就是一种操作定义为一个类。

### 从问题开始说起

举个例子，现在我们要实现一个计算器的类，开始我们会定义成

```java
/**
 * 计算器类
 */
public class Calculator {

    /***
     * 加
     * */
    public void operateAdd(int num1, int num2) {
        System.out.println(num1 + num2);
    }

    /***
     * 减
     * */
    public void operateSub(int num1, int num2) {
        System.out.println(num1 - num2);
    }

    /***
     * 乘
     * */
    public void operateMul(int num1, int num2) {
        System.out.println(num1 * num2);
    }

    /***
     * 除
     * */
    public void operateDiv(int num1, int num2) {
        System.out.println(num1 / num2);
    }

}
```

好，代码完成之后，看起来没什么问题，你兴致勃勃的打了一个jar包，并且供其他人引用。

没过了多久，有人找到你：“我想增加个计算次方的功能，要怎么做”，这时候，你就要在你的`Calculator`类里面再加个方法，如下

```java
/***
     * 次方
     * */
public void operatePow(int num1, int num2) {
    System.out.println(Math.pow(num1, num2));
}
```

仔细想一想，这样有一个很严重的问题，以后每个人如果要实现自己的算法，难道都要找你么？而且这种做法也违背了设计模式中的开闭原则：**开闭原则(Open-Closed Principle, OCP)：一个软件实体应当对扩展开放，对修改关闭。即软件实体应尽量在不修改原有代码的情况下进行扩展。**

### 考虑使用策略模式

现在我们用策略模式来改写一下，我们首先声明一个计算器的接口。

```java
/**
 * 计算器策略类
 */
public interface CalculatorOperation {
    /**
     * 操作
     * **/
    void operate(int num1, int num2);
}

```

然后根据策略模式的思想，将一种操作定义为一个类

```java
/**
 * 计算器加法类
 */
public class CalculatorAdd implements CalculatorOperation {

    /**
     * 操作
     **/
    @Override
    public void operate(int num1, int num2) {
        System.out.println(num1 + num2);
    }
}

/**
 * 计算器减法类
 */
public class CalculatorSub implements CalculatorOperation {

    /**
     * 操作
     *
     **/
    @Override
    public void operate(int num1, int num2) {
        System.out.println(num1 - num2);
    }
}

//其余类省略。。
```

如果想为计算器增加一个操作，使用者就可以直接继承此接口并实现自己的逻辑

```java
/**
 * 计算次方
 */
public class CalculatorPow implements CalculatorOperation {

    /**
     * 操作
     *
     **/
    @Override
    public void operate(int num1, int num2) {
        System.out.println(Math.pow(num1, num2));
    }
}
```

在使用的时候就可以直接

```java
int num1 = 5;
int num2 = 2;

CalculatorOperation o = new CalculatorPow();

o.operate(num1, num2);
```

别人如果想拓展你的算法，就可以直接继承这个类，遵循了设计模式中的开闭原则。

### 加入配置文件的使用

上文中，我们简单讲了一下策略模式。但是在正常的项目中，不一定会通过创建对象的方式来使用，这个时候，我们就可以使用配置文件配置一个默认执行的算法类，其它人如果想改变，直接改变此配置就可以了。

首先在配置文件中加入一个配置项

```properties
#策略模式中，计算器要执行的操作类路径  这里我们就指定执行加法
strategy.operater.class = CalculatorAdd
```

然后编写我们的处理器，这里我直接用`main`方法代替

```java
private static Properties prop = new Properties();

private static final String CLASS_NAME_KEY = "strategy.operater.class";

static void init() throws IOException {

    //读取到在配置文件中配置的默认执行类
    InputStream resourceAsStream = Test.class.getClassLoader().getResourceAsStream("application.properties");

    prop.load(resourceAsStream);
}

public static void main(String[] args) {
    int num1 = 5;
    int num2 = 2;

    try {
        init();
        //获取执行器
        Class<?> aClass = Class.forName(prop.getProperty(CLASS_NAME_KEY));

        CalculatorOperation o = (CalculatorOperation) aClass.newInstance();

        o.operate(num1, num2);

    } catch (IOException e) {
        System.err.println(e);
    } catch (ClassNotFoundException e) {
        System.err.println("类未找到!");
    } catch (IllegalAccessException | InstantiationException e) {
        e.printStackTrace();
    }

}

```

这样一来，别人如果想改变默认的执行器，自己定义一个类，然后修改配置文件中的位置就可以了。
