## 装饰模式

> 在面向对象的编程中，装饰器模式是一种设计模式，它允许动态地将行为添加到单个对象，而不会影响来自同一类的其他对象的行为。简单来说，就是我们可以在不影响指定对象的情况下为其添加功能。

### 组成

装饰模式主要由两个角色组成，一个是被装饰的对象，另外一个就是装饰器。首先来看一下`UML`结构图

![](/images/oss/%E5%8D%9A%E5%AE%A2/%E8%A3%85%E9%A5%B0%E6%A8%A1%E5%BC%8FUML.png)

上图中，`component`是被装饰对象的统一接口，`component`就是被装饰的对象。`Decorator`是装饰器的统一接口，`Decorator1`，`Decorator2`是装饰器。

### 详解

设想一下，现在我们要做一个游戏，游戏中有你的人物，人物初始化时都是没有装备的，但是随着游戏进度的进行，你的人物肯定需要穿上装备，那么如果你佩戴了一把武器之后，我们的代码难道要重新去修改游戏人物的`Class`类么，以后再穿上一件防具呢？如果要修改源代码，那么就违背了之前我们提过的**开闭原则(Open-Closed Principle, OCP)。**

考虑到人物的武器和防具都不是固定的，而且需要武器和防具需要改变人物的属性（攻击力防御力等），此时看一下我们在文章开始对装饰模式的说明**装饰模式允许动态地将行为添加到单个对象，而不会影响来自同一类的其他对象的行为**，是不是特别符合这种情况呢？

首先创建我们的游戏人物接口

```java
public interface Person {

    /**
     * 获取人物姓名
     * **/
    String getName();

    /**
     * 获取人物攻击力
     * **/
    int getAttack();

    /**
     * 获取人物防御力
     * **/
    int getDefensive();

    /**
     * 打印人物属性
     * **/
    void printProperties();

}
```

然后创建出我们的实际角色，这里我们叫它`Warrior`

```java
public class Warrior implements Person {

    /**
     * 攻击力
     **/
    private int attack;

    /**
     * 防御力
     **/
    private int defensive;

    /**
     * 人物姓名
     **/
    private String name;

    public Warrior() {
        //初始化人物属性都是0
        attack = 0;
        defensive = 0;
        name = this.getClass().getSimpleName();
        System.out.println("人物刚刚出生，身上什么都没有");
    }

    /**
     * 获取人物姓名
     **/
    @Override
    public String getName() {
        return name;
    }

    /**
     * 获取人物攻击力
     **/
    @Override
    public int getAttack() {
        return attack;
    }

    /**
     * 获取人物防御力
     **/
    @Override
    public int getDefensive() {
        return defensive;
    }

    /**
     * 打印人物属性
     **/
    @Override
    public void printProperties() {
        System.out.printf("warrior的攻击力为：%d\t防御力为：%d\n", getAttack(), getDefensive());
    }


}
```

第三步创建我们的装饰器接口

```java
public abstract class PersonDecorator implements Person {

    protected Person person;

    public PersonDecorator(Person person) {
        this.person = person;
    }

    /**
     * 获取人物姓名
     **/
    @Override
    public String getName() {
        return person.getName();
    }

    /**
     * 打印人物属性
     **/
    @Override
    public void printProperties() {
        System.out.printf("warrior的攻击力为：%d\t防御力为：%d\n", this.getAttack(), this.getDefensive());
    }
}
```

第四步就是我们的装饰器类了，这里我们模拟两个装饰器，分别是武器：铁锤（`mace`）和防具：铁甲（`armor`）

首先创建武器的装饰类

```java
public class Mace extends PersonDecorator {

    public Mace(Person person) {
        super(person);
        System.out.printf("%s装备上了铁锤，攻击力增加10点！\n", person.getName());
    }

    /**
     * 获取人物攻击力
     **/
    @Override
    public int getAttack() {
        return person.getAttack() + 10;
    }

    /**
     * 获取人物防御力
     **/
    @Override
    public int getDefensive() {
        return person.getDefensive();
    }

}
```

然后是防具的装饰类

```java
public class Armor extends PersonDecorator {

    public Armor(Person person) {
        super(person);
        System.out.printf("%s装备上了铁甲，防御力增加10点！\n", person.getName());
    }

    /**
     * 获取人物攻击力
     **/
    @Override
    public int getAttack() {
        return person.getAttack();
    }

    /**
     * 获取人物防御力
     **/
    @Override
    public int getDefensive() {
        return person.getDefensive() + 10;
    }

}
```

使用时，如果我们想给人物装备上武器

```java
Person person = new Mace(new Warrior());
person.printProperties();
```

运行结果为

```java
人物刚刚出生，身上什么都没有
Warrior装备上了铁锤，攻击力增加10点！
warrior的攻击力为：10	防御力为：0
```

如果同时装备武器和防具

```java
Person person = new Armor(new Mace(new Warrior()));
person.printProperties();
```

运行结果为

```java
人物刚刚出生，身上什么都没有
Warrior装备上了铁锤，攻击力增加10点！
Warrior装备上了铁甲，防御力增加10点！
warrior的攻击力为：10	防御力为：10
```

这样一来，是不是就方便了许多呢，而且代码极易拓展。将来我们想让人物穿上鞋子的话也只需要创建一个类就可以了。

### 实际应用

对装饰器模式最典型的应用应该就是`Java`中的`I/O`了，如下

```java
String fileName = "E:\\test.txt";

//创建一个普通的文件输入流
DataInputStream in = new DataInputStream(new FileInputStream(fileName));

//创建一个带缓冲功能的文件输入流
DataInputStream in = new DataInputStream(
    new BufferedInputStream(new FileInputStream(fileName)));
```

假如我们想再自定义一个文件流，如把文件中的小写字母全部转换为大写，也只需要拓展一个装饰器就可以了。

```java
public class UpperCaseInputStream extends InputStream {

    private FileInputStream fileInputStream;

    public UpperCaseInputStream(FileInputStream fileInputStream) {
        this.fileInputStream = fileInputStream;
    }

    @Override
    public int read() throws IOException {
        int read = fileInputStream.read();

        //把小写字母全部转换为大写
        if(read > 96 && read < 123) {
            read -= 32;
        }

        return read;
    }
}
```

在使用的时候，也只需要修改一句就可以了

```java
DataInputStream dataInputStream = new DataInputStream(new UpperCaseInputStream(new FileInputStream("test.txt")));
```

### 优缺点

装饰模式的优点很容易看出来，可以在不改变原有类的基础上增加新的功能。不过缺点也是有的，如果装饰器过多的话，可能会让系统比较复杂，并且代码可能不太容易理解。
