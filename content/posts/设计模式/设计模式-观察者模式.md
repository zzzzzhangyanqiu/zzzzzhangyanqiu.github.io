### 定义

> **观察者模式**是一种行为设计模式， 允许你定义一种订阅机制， 可在对象事件发生时通知多个 **观察** 该对象的其他对象。

### 举例

有一家报社，每次新报刊出版的时候，都要询问附近的每个人家需不需要，这样一来有两个问题，有的人不需要，就会把报社的行为当做是骚扰。而报社也因为要询问每一家，浪费了人力物力。那是不是可以让需要的人来报社这里订阅报刊，有新报刊出版的时候，报社也只需要为订阅的人送一份就可以了。

### 组成

观察者模式有三个角色，分别是发布者、订阅者和具体订阅者，整体类图如下

![image-20201013141003315](/images/oss/PicGo/image-20201013141003315.png)

#### 发布者

持有订阅者的引用，负责在状态发生时通知订阅者，也就是上面例子中的报社角色

#### 订阅者

订阅者通常是一个接口，声明通知方法

#### 具体订阅者

作为订阅者接口的实现，在通知方法中可以实现自己的逻辑

### 实现

前面说了那么多，下面开始代码实现，首先创建报刊订阅用户，也就是订阅者

```java
public interface Subscriber {
    /**
     * 这里以报刊名称作为入参
     * */
    void update(String paperName);
}
```

接下来是我们的订阅用户实现类，也就是具体订阅者，这里创建两种通知方式，分别是短信和邮件的方式

```java
public class EmailSubscriber implements Subscriber {

    private final String userName;

    public EmailSubscriber(String userName) {
        this.userName = userName;
    }

    @Override
    public void update(String paperName) {
        System.out.println("邮件通知用户" + userName + "——新报刊：" + paperName + "已经发表");
    }
}
 
public class MessageSubscriber implements Subscriber {

    private final String userName;

    public MessageSubscriber(String userName) {
        this.userName = userName;
    }

    @Override
    public void update(String paperName) {
        System.out.println("短信通知用户" + userName + "——新报刊：" + paperName + "已经发表");
    }
}

```

最后创建我们的报刊对象，也就是发布者

```java
public class Publisher {
    /**
     * 保存订阅者的引用
     */
    List<Subscriber> subscribers;

    public Publisher() {
        subscribers = new ArrayList<>();
    }

    public void subscribe(Subscriber s) {
        subscribers.add(s);
    }

    public void unSubscribe(Subscriber s) {
        subscribers.remove(s);
    }

    /**
     * 新报刊发表时通知所有订阅者
     * */
    public void notifySubscribers(String paperName) {
        for (Subscriber subscriber : subscribers) {
            subscriber.update(paperName);
        }
    }
}
```

最后是客户端使用，这里创建`A、B`两个用户，分别以短信和邮件方式通知

```java
public static void main(String[] args) {
    //A用户  邮件通知
    Subscriber a = new EmailSubscriber("A");
    //B用户  短信通知
    Subscriber b = new MessageSubscriber("B");
    //创建发布者
    Publisher publisher = new Publisher();
    //订阅通知
    publisher.subscribe(a);
    publisher.subscribe(b);
    //模拟新报刊发表
    publisher.notifySubscribers("新华报第一期");
}
```

上述代码运行结果为

```java
邮件通知用户A——新报刊：新华报第一期已经发表
短信通知用户B——新报刊：新华报第一期已经发表
```

### 总结

#### 优点

**观察者模式**的优点很突出，如果增加了新的订阅者类，无需改动原来的代码，符合开闭原则，而且可以在运行时才建立和对象之间的关系

#### 缺点

**观察者模式**的缺点也很明显，就是我们无法决定通知的顺序，不过可以在订阅者中加入一个排序字段来解决

### 其它

需要注意的是，`Java`本身也提供了对应的观察者类库库类[`java.util.Observer`](https://docs.oracle.com/en/java/javase/11/docs/api/java.base/java/util/Observer.html)和[`java.util.Observable`](https://docs.oracle.com/en/java/javase/11/docs/api/java.base/java/util/Observable.html)，但在`Java 9`中已弃用它们，因为实现的模型非常有限，所以这里就不在介绍了，感兴趣的同学可以自行学习
