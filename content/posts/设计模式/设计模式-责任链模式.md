### 场景：

假设我们现在需要编写一个日志记录程序，该程序需要根据不同的日志级别有不同的记录方式（如控制台输出、记录到文件、甚至发送邮件预警等等）。

### 问题

针对上述的需求，首先我们开始编写代码

```java
public class Logger {

    /**
     * 日志级别
     ***/
    public enum LogLevel {

        INFO, DEBUG, WARNING, ERROR;

        public static LogLevel[] all() {
            return values();
        }

    }

    void message(String msg, LogLevel logLevel) {
        //任何类型都使用info进行处理
        System.out.println("info：" + msg);
        if (logLevel.equals(LogLevel.ERROR)) {
            System.err.println("error：" + msg);
        }
    }

    public static void main(String[] args) {
        Logger logger = new Logger();
        logger.message("aaa", LogLevel.INFO);
        logger.message("bbb", LogLevel.ERROR);
    }

}
```

很快，我们编写好了自己的代码，测试了一下，OK没什么问题。但是仔细看上面的代码，其实已经违背了面向对象的几个原则，1、`单一职责原则`：很明显，我们的`Logger`这一个类，需要处理所有级别的日志输出，如果日志的级别较多，该类的代码会越来越臃肿。2、`开闭原则`：如果我们需要再增加一个级别的日志处理，需要再次修改`Logger`类。针对上述情况，我们考虑使用`责任链模式`

### 责任链模式

如果你想让一个以上的对象处理请求的时候，责任链模式就非常适合了，责任链模式的定义如下

**责任链模式**是一种由命令对象的源和一系列**处理对象**组成的设计模式。每个处理对象都包含定义其可以处理的命令对象类型的逻辑。其余的将传递到链中的下一个处理对象。还存在一种将新处理对象添加到此链末尾的机制。

大概意思就是，我们可以把所有的处理器组成一条链，每个处理器都保留着下一个处理器的引用。使用时，从第一个处理器开始调用，如果对应的处理器不能处理业务逻辑，就交给下一个处理，一直到最后一个处理器为止。

责任链模式由以下三个角色构成

1、**抽象处理者(Handler)角色：**定义出一个处理请求的接口。如果需要，接口可以定义出方法以设定和返回对下家的引用。

2、**具体处理者(ConcreteHandler)角色：**具体处理者接到请求后，可以选择将请求处理掉，或者将请求传给下家。

3、**客户端(client)角色：**负责程序的调用

#### 实现

大概了解责任链模式之后，我们开始改写以上代码，首先创建抽象处理者角色，这里我们使用抽象类来实现

```java
public abstract class Logger {

    /**
     * 日志级别
     * ***/
    public enum LogLevel {

        INFO, DEBUG, WARNING, ERROR;

        public static LogLevel[] all() {
            return values();
        }

    }

    /**
     * 对应的处理器能够处理的日志级别
     * ***/
    Set<LogLevel> LOG_LEVELS = new HashSet<>();

    abstract void message(String msg, LogLevel logLevel);

    /***
     * 添加链中的下一个处理器
     * **/
    Logger addNextLog(Logger nextLog) {
        return new Logger() {
            @Override
            public void message(String msg, LogLevel logLevel) {
                Logger.this.message(msg, logLevel);
                nextLog.message(msg, logLevel);
            }
        };
    }

    /**
     * 记录日志
     * **/
    void logger(LogLevel logLevel, String msg, Consumer<String> log){
        if(LOG_LEVELS.contains(logLevel)) {
            log.accept(msg);
        }

    }
}
```

然后创建两个具体处理器，分别是处理`Error`级别的日志和`Info`级别的日志

```java
public class InfoLogger extends Logger{


    public InfoLogger(LogLevel... logLevels) {
        LOG_LEVELS.addAll(Arrays.asList(logLevels));
    }


    @Override
    public void message(String msg, LogLevel logLevel) {
        Consumer<String> log = (x) -> System.out.println("InfoLogger：" + x);
        logger(logLevel, msg, log);

    }
}

public class ErrorLogger extends Logger{


    public ErrorLogger(LogLevel... logLevels) {
        LOG_LEVELS.addAll(Arrays.asList(logLevels));
    }


    @Override
    public void message(String msg, LogLevel logLevel) {
        Consumer<String> log = (x) -> System.err.println("ErrorLogger：" + x);
        logger(logLevel, msg, log);

    }
}
```

最后在客户端组成一条链，并调用第一条链就可以了

```java
//所有级别的日志都需要经过info处理
Logger logger = new InfoLogger(Logger.LogLevel.all())
    .addNextLog(new ErrorLogger(Logger.LogLevel.ERROR));    //添加error日志处理器

logger.message("记录日志信息", Logger.LogLevel.INFO);

logger.message("记录错误信息", Logger.LogLevel.ERROR);
```

#### 优劣

我们来看一下使用了责任链模式的好处

首先符合面向对象中的**单一职责原则**和**开闭原则**，每一个具体处理者都负责一个业务逻辑，如果要增加处理者，只需要创建新的类，并且在客户端增加引用就可以了

当前，责任链模式也有不好的地方

1、很大的增加了类的数量

2、由于是链式调用，在代码调试时不方便，容易混淆思路
