## 适配器模式

> 软件工程中，适配器模式是一种软件设计模式，它允许将现有类的接口用作另一个接口。它通常用于使现有类与其他类一起工作而无需修改其源代码

适配器模式，简单来说，就是把一个现有类的接口，转换成期望的接口，让原本两个不兼容的类可以一起工作。

### 组成

设配器模式由三个部分组成，分别是

1. 目标接口(`Target`)：提供给外界调用的接口
2. 适配器(`Adapter`)：进行适配工作
3. 被适配对象(`Adaptee`)：最终被调用的方法

举个例子，从去年开始，苹果手机就已经取消3.5mm耳机接口，而是使用充电口代替。这样以来，圆形插头的耳机就不能直接在苹果手机上使用了，这时候就需要借助苹果提供的耳机适配器

![](/images/oss/%E5%8D%9A%E5%AE%A2/%E8%8B%B9%E6%9E%9C%E8%80%B3%E6%9C%BA%E8%BD%AC%E6%8E%A5%E5%A4%B4.png)

在这个场景中，耳机适配器扮演了适配器角色，耳机的原型插头就相当于目标接口(`Target`)角色，苹果手机的充电孔就是被适配的角色。下面通过代码一起了解一下此模式（为了方便，这里以方法参数的不同模拟插口形状的不同）。

### 代码

首先创建苹果手机类，也就是我们的被适配对象(`Adaptee`)

```java
/**
 * 苹果手机类，苹果手机的耳机连接插口是充电口
 * 这里就以String类型参数模拟
 */
public class ApplePhone {
    /**
     * 耳机接口
     *
     * **/
    public void headPhoneInterface(String string) {
        System.out.println("已经连接苹果手机");
    }
}
```

耳机类，这里的角色是`client`

```java
/**
 * 耳机类
 */
public class HeadPhone {
    /**
     * 耳机的插头形状
     **/
    int shape = 1;

    /**
     * 连接手机
     ***/
    void connectPhone() {

    }
}
```

耳机类的插头形状是原型的（这里用`int`模拟），而苹果手机的插口却是方形的（这里用`String`模拟），这样调用肯定会出错，有的同学可能会说，直接把苹果手机的接口参数类型改成`int`不就好了么。正常情况下是没错的，不过此方法如果已经被系统中其它地方调用了呢？牵一发而动全身。所以我们这时候要在两个对象之间加一个适配器

```java
/**
 * 适配器接口
 */
public interface HeadPhoneInterface {
    /**
     * 连接手机，我们这里以参数类型的不同模拟插头形状的不同
     * 统一的耳机插头都是圆形
     **/
    public void connectPhone(int circle);
}

/**
 * 苹果手机耳机适配器
 */
public class ApplePhoneAdapter implements HeadPhoneInterface {

    private ApplePhone applePhone = new ApplePhone();

    /**
     * @param circle
     */
    @Override
    public void connectPhone(int circle) {
        //将原型接口适配成苹果手机接口
        applePhone.headPhoneInterface(String.valueOf(circle));
    }
}
```

然后我们的耳机类就可以调用适配器类

```java
/**
 * 耳机类
 */
public class HeadPhone {
    /**
     * 耳机的插头形状
     **/
    int shape = 1;

    /**
     * 适配器类
     **/
    private HeadPhoneInterface headPhoneInterface;

    public HeadPhone() {
        headPhoneInterface = new ApplePhoneAdapter();
    }

    /**
     * 连接手机
     ***/
    void connectPhone() {
        //连接手机  此时我们不需要管耳机的形状，只需要直接调用就可以了
        //其它工作都交给适配器来做
        headPhoneInterface.connectPhone(shape);
    }


    public static void main(String[] args) {
        //测试代码
        HeadPhone headPhone = new HeadPhone();
        headPhone.connectPhone();
    }
}
```

### 实际使用

`Mybatis`中集成了很多第三方日志框架，但是每个框架提供了API都各不形同，所以`Mybatis`自己定义了一个统一的`log`接口对外提供，然后使用适配器模式分别调用不用框架的API。有兴趣的同学可以看下[这篇文章](https://suiyueranzly.gitee.io/posts/3680112987/)

### 优点

适配器模式的优点很明显，复用现有的组件，可以让两个不兼容的类一起运行，而无需修改旧代码。

### 缺点

同样，缺点也十分明显，过多的适配器导致系统复杂度加大，因为你调用的是适配器，而你并不知道此适配器调用到了哪个方法。所以不建议在系统一开始的时候就使用适配器。
